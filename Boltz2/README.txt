# PPI-Graphomer — HPCC Workflow (MSU)

## Goal
Use **ppi-graphomer** on the MSU HPCC to run inference on predicted protein structures (**.pdb**) and collect outputs (single-file runs and batch runs), while avoiding common HPCC storage/quota issues.

## What we used as input
- **PDB structure files** (e.g., structures generated by Boltz/AlphaFold/BioEmu, etc.).
- A working directory on HPCC for the repo (`~/ppi-graphomer`).
- A **large, writable storage location** for caches + outputs (recommended: `/mnt/ufs18/...`).

## Where the work happened
- We connected to an HPCC **development node** (Open OnDemand terminal / VS Code Remote-SSH). This was used for editing files, quick testing, and preparing scripts.
- The heavy computation should run as a **SLURM job** on HPCC compute nodes for long batches (dev nodes have time limits).
- Large outputs/caches were kept on **/mnt/ufs18/...** to avoid **HOME quota** and scratch write issues.

## Main steps (conceptual)
1) **Connect and set up a workspace**
   - Connected to an HPCC dev node.
   - Used `~/ppi-graphomer` as the repo working directory.
   - Chose a large filesystem (`/mnt/ufs18/...`) for caching models and storing results/logs.

2) **Create and activate the conda environment**
   - Loaded `Miniforge3`.
   - Created/activated a conda env (e.g., `ppi-graphomer`) and installed required Python packages.

3) **Redirect model caches + temp files (CRITICAL on HPCC)**
   - Redirected **HuggingFace / Torch hub caches** and **TMPDIR** to `/mnt/ufs18/...`.
   - This prevents `Disk quota exceeded` and `No space left on device` errors caused by HOME quota or restricted scratch writes.

4) **Prepare PDB inputs (single file or batch folder)**
   - Placed all PDB files into one folder (e.g., `/mnt/gs21/scratch/<netid>/BoltZ_PDB/`).
   - If PDB filenames were complex (e.g., Boltz outputs like `01_...__..._model_0.pdb`), created **simplified copies** to avoid `KeyError` in `inference.py`.

5) **Run ppi-graphomer inference**
   - Ran a **single PDB** first to validate environment + caches.
   - Then ran **batch inference** over a folder of PDB files, saving:
     - one log per PDB
     - a summary CSV (`results.csv`)

6) **Collect outputs**
   - Results CSV and logs were stored on `/mnt/ufs18/...` so they persist and do not consume HOME quota.

## Deliverables
- **Batch results table**: `results.csv` (one row per PDB; includes a summary output line)
- **Per-PDB logs**: one `.log` file per structure
- (Optional) A simplified PDB folder for stable inference runs (`BoltZ_PDB_simple/`)

## Notes
- This repo is intended to store workflow documentation and scripts.
- Do **not** commit large model caches/weights or giant output folders to GitHub.
